# Janykadam — телеграм-бот марафонов и бэкенд панели

Бот 30-дневных марафонов сообщества Janykadam и API для
[админ-панели](../admin-panel). Node 22, TypeScript, NestJS на Fastify-адаптере,
PostgreSQL 16 через Drizzle, очереди на pg-boss.

## Главный факт

**Один бот обслуживает все марафоны.** Отсюда почти всё устройство:

- вход только по deep link с кодом марафона — `t.me/<бот>?start=<код>`;
  бот не может написать первым;
- имя, описание, команды и аватар бота общие, их нельзя развести по марафонам;
- тихие часы и лимит напоминаний в день тоже общие: чат у участницы один.
  Лимит по умолчанию 0 — напоминание приходит о каждой теме;
- участница может вести два марафона сразу. Активный марафон один, каждое
  напоминание начинается с метки `[Название]`, а кнопка в нём переключает контекст.

**Отчёт — только видеокружок.** Он не проверяется: отправка в открытое окно и
есть принятый отчёт. Видео не хранится: в базе только `file_id`,
`file_unique_id` и длительность. В канал марафона бот перезаливает кружок на
лету, ничего не сохраняя на диск.

**У каждого марафона свой канал отчётов** — там участницы видят видео друг
друга. Подробности ниже, в разделе «Канал отчётов».

Команд, капитанов, кодов команд, модерации и других типов подтверждения не
существует — это проверяется тестом `tests/removed-features.test.ts`.

## Как идёт участница

1. `/start <код>` по ссылке марафона. Язык спрашивается при каждом входе:
   кнопки меню и все тексты дальше — на выбранном языке.
2. Место: кнопка города, поиск по названию или геолокация. Из геолокации
   берётся ближайший город GeoNames — крупный город в 15 км побеждает соседнее
   село. Уже выбранное место можно оставить одной кнопкой «📍 Калтыруу: …».
3. Правила марафона — свои у марафона или общие из текстов бота. Без согласия
   записи нет.
4. Цель — своими словами, до 200 знаков; можно отложить.
5. Приветствие, главное меню и кнопка в канал марафона.

Главное меню — шесть кнопок, надписи лежат в текстах бота и правятся в панели:
«🎥 Отчёт тапшыруу», «✅ Отчётторум», «🤲 Максаттарым», «😎 Өзүм жөнүндө»,
«🕐 Убакыт алкагы», «❓ Жардам». Нажатие узнаётся по тексту на обоих языках,
а старые надписи прежней клавиатуры тоже понимаются — и клавиатура заменяется.

- **Отчётторум** — темы дня с окнами `06:21–07:47` и отметкой: сдано, узур,
  ещё не открылось, идёт, пропущено.
- **Өзүм жөнүндө** — рейтинг (пятёрка лучших и своё место), цель и кнопка
  «🤍 узур күнү»: сегодняшние намазы можно не сдавать, свои темы остаются.
- **Напоминания** — при открытии каждой темы. Попавшие в тихие часы сдвигаются
  на их конец; Тахажуд — только тем, кто включил `/tahajjud`.

Команды: `/start`, `/otchet`, `/ball`, `/marafon`, `/pauza`, `/zona`, `/til`,
`/tahajjud`, `/help`.

## Канал отчётов

Бот не может создать канал и не может добавить туда людей — это ограничение
Telegram. Поэтому:

1. Админ создаёт частный канал и вставляет его ссылку в панель — без неё
   марафон не создать. Ссылки на канал и на группу выглядят одинаково
   (`t.me/+…`), поэтому бэкенд открывает страницу предпросмотра t.me и
   принимает только канал («subscribers», «Join Channel»). Группа и отозванная
   ссылка отклоняются; если t.me не ответил, ссылка проходит.
2. Админ добавляет бота в канал администратором — кнопкой
   `t.me/<бот>?startchannel&admin=post_messages+invite_users+restrict_members`
   или вручную. Бот получает `my_chat_member`, записывает канал в
   `bot_channels` и узнаёт марафон по основной ссылке канала или по его
   имени. Не совпало — панель предложит выбрать канал вручную.
3. Бот создаёт свою ссылку с заявкой (`creates_join_request`) и пишет в канал
   первое сообщение. Участница получает эту ссылку кнопкой после записи (кто
   записался раньше — фоновым заданием), а заявки по ней бот одобряет только
   участницам марафона. Заявки по чужим ссылкам он не трогает.
4. Принятый отчёт встаёт в очередь (`reports.channel_state = 'pending'`).
   Раз в минуту задание `channel-sync` публикует очередь: кружок скачивается и
   уходит обычным видео с подписью — у видеокружков подписей не бывает, а
   сменить тип файла по `file_id` Telegram не даёт. Не скачался (больше
   20 МБ) — кружок и подпись ответом. Пауза между постами в канал — 3 секунды:
   Telegram пускает около 20 сообщений в минуту в один чат.
5. Исключённую из марафона бот выводит из канала (`unbanChatMember` без
   `only_if_banned`): вернётся в марафон — вступит снова.

Без готового канала — бот админ, может публиковать и приглашать — проверка
конфигурации блокирует запуск марафона.

## Быстрый старт

```bash
corepack pnpm install
```

Поднять базу (PostgreSQL 16) и применить миграции:

```bash
docker compose up -d db
```

```bash
cp .env.example .env
```

```bash
corepack pnpm db:migrate
```

Справочник городов (≈170 тысяч строк, скачивается один раз):

```bash
corepack pnpm import:geonames
```

Базовые данные и демо-марафон:

```bash
SEED_DEMO=true corepack pnpm seed
```

Запуск:

```bash
corepack pnpm build && corepack pnpm start
```

### Про pnpm и Node

pnpm берётся через `corepack` — версия закреплена в поле `packageManager`, а
Node 22 в `.tool-versions`. Если `pnpm` в системе привязан к другой версии Node,
используйте `corepack pnpm` вместо голого `pnpm`.

### Разработка

`tsx` не умеет `emitDecoratorMetadata`, поэтому приложение всегда запускается из
`dist`: без метаданных DI в NestJS получает `undefined`. В двух терминалах:

```bash
corepack pnpm build:watch
```

```bash
corepack pnpm start:dev
```

Скрипты (`db:migrate`, `seed`, `import:geonames`, `compare:aladhan`) декораторов
не содержат и работают под `tsx` напрямую.

## Настройка в BotFather

1. `/newbot` — получить токен, положить в `BOT_TOKEN`.
2. `/setprivacy` → **Disable**, иначе бот не увидит сообщения в группах. Для
   работы это не нужно (бот работает в личке и администратором в каналах
   марафонов, а из групп выходит), но отключённый privacy mode избавляет от
   сюрпризов.
3. `/setdomain` — домен админ-панели. **Без этого шага Telegram Login Widget не
   работает**: виджет отказывается отдавать данные на незарегистрированный домен.
4. Имя, описание и команды задаются из панели (`PATCH /api/bot/settings`,
   `POST /api/bot/name`), менять их в BotFather не нужно.

## Переменные окружения

| Переменная | Смысл |
| --- | --- |
| `TZ` | Обязательно `UTC`. Процесс падает на старте, если это не так. |
| `BOT_TOKEN` | Токен из BotFather. |
| `BOT_MODE` | `polling` в разработке, `webhook` в проде. |
| `PUBLIC_URL` | Публичный адрес для вебхука (только в режиме webhook). |
| `WEBHOOK_SECRET` | Проверяется в заголовке `X-Telegram-Bot-Api-Secret-Token`. |
| `DATABASE_URL` | PostgreSQL 16. |
| `SESSION_SECRET` | Подпись куки админ-сессии. |
| `ADMIN_ORIGIN` | Origin панели для CORS. |
| `INITIAL_ADMIN_TG_USERNAME` | Кого сид делает первым админом. |
| `SEED_DEMO` | `true` — создать демо-марафон. |
| `MAX_MSG_PER_SECOND` | Общий предел отправки, по умолчанию 25. |

Секреты генерируются так:

```bash
openssl rand -hex 32
```

`.env` читают и приложение, и скрипты, и тесты. Переменные окружения имеют
приоритет над файлом, но `db:migrate`, `seed` и `import:geonames` сначала
сверяют `DATABASE_URL`: если он задан в оболочке и не совпадает с `.env`,
скрипт останавливается. Это не придирка — `DATABASE_URL` другого проекта,
экспортированный в профиле, однажды увёл миграции в постороннюю базу.

## Время намазов

Считается локально пакетом `adhan`, в рантайме никаких обращений к API.
Метод — Aladhan № 14 (ДУМ России): Фаджр 16°, Иша 15°, Аср по ханафитскому
мазхабу, высокоширотное правило `recommended`.

Пояс выводится из координат, а не выбирается отдельно: время намаза зависит от
точки. Бишкек и Ош лежат в `Asia/Bishkek`, но расходятся на 5–15 минут.

Сверка с эталоном (инструмент разработчика, в проде не используется):

```bash
corepack pnpm compare:aladhan 2026-11-08
```

Расхождение — ноль по всем временам, кроме Асра: там 1–2 минуты из-за разного
округления длины тени. Выравнивается поправками `bot_settings.prayer_tune`.

Окна намазов полуоткрытые `[открыто, закрыто)` и могут пересекать полночь.
Куптан идёт до следующего фаджра: в Петербурге 21 июня иша наступает в 23:10, и
правило «до полуночи» оставляло бы меньше часа. Отчёт всегда относится к ключу
дня своего окна, а не к календарной дате отправки.

## Города

Поиск по выгрузке GeoNames `cities1000`. И запрос, и индекс сводятся к одной
латинской форме, поэтому «Талас», «Talas» и опечатка «Бишкэк» находят одно и то
же. Кыргызские буквы складываются: `ң→н`, `ө→о`, `ү→у`.

Ранжирование трёхъярусное: точное совпадение с основным именем, затем совпадение
словом среди альтернативных названий, затем триграммы; внутри яруса — по
населению. Без ярусов «Ош» тонул под Лондоном и Найроби: в их `alternatenames`
встречается форма, которая после свёртки даёт слово `osh`.

**Данные о городах: GeoNames (CC BY 4.0), https://www.geonames.org/** — атрибуция
обязана оставаться здесь и в тексте `/help`.

## Что где лежит

```
src/
  config/     разбор окружения
  db/         схема Drizzle, миграции, сид и тексты бота, поиск городов
  domain/     чистая логика: намазы, окна, баллы, напоминания, валидация,
              меню, ссылка на канал
  services/   участницы, отчёты, темы, тексты и настройки, места, каналы,
              рассылки — их делят бот, задания и API
  bot/        grammY: контекст, клавиатуры, флоу регистрации, отчёта, профиля
              и команд, заявки в канал
  jobs/       pg-boss: планировщик, напоминания, сводки, оценка дня,
              рассылки, канал отчётов
  api/        админ-API, вход через Telegram Login, вебхук, /healthz
  scripts/    импорт GeoNames, сверка с Aladhan
drizzle/      миграции
tests/
```

`domain/` не импортирует ни Telegram, ни базу — поэтому её логика проверяется
обычными тестами без окружения.

## Тесты

```bash
corepack pnpm test
```

Нужны применённые миграции, импортированные города и выполненный сид (с
`SEED_DEMO=true`): часть тестов работает на настоящем Postgres, а флоу бота —
через подменённый Telegram API, наружу ничего не уходит, включая t.me — его
страницы подменены образцами из `tests/fixtures`. База одна на все файлы,
поэтому они идут последовательно.

Если в оболочке экспортирован чужой `DATABASE_URL`, запускайте без него —
тесты берут базу из `.env`:

```bash
env -u DATABASE_URL corepack pnpm test
```

pg-boss в тестах тоже поддельный: задания не исполняются по расписанию, а
складываются в массив, а планировщик и воркеры вызываются напрямую. Так
проверяется и что поставлено в очередь, и что произойдёт, когда задание
сработает — включая день перехода на зимнее время и рассылку на тысячу
получателей.

## Эксплуатация

Вебхук проверяет секретный заголовок и отсеивает повторные `update_id` за сутки.
Отправка ограничена 25 сообщениями в секунду — общий лимитер на напоминания и
рассылки, поэтому рассылка на 500 человек занимает около двадцати секунд.

`/healthz` проверяет и базу, и pg-boss: без очереди напоминания перестают
уходить совершенно молча.

Координаты округляются до двух знаков. В логи не попадают ни тексты сообщений,
ни ответы на вопросы — только идентификаторы.

Наружу бэкенд ходит в два места: `api.telegram.org` (Bot API и скачивание
кружков для канала) и `t.me` (проверка, что ссылка ведёт в канал). Время
намазов и города считаются локально.

Новые тексты бота дописываются в базу при старте, а правленые из панели не
трогаются, поэтому сид на обновлении не нужен. При старте же чинятся места,
сохранённые раньше как надпись кнопки геолокации.

### Деплой

```bash
docker compose up -d --build
```

Затем внутри контейнера применить миграции, справочник городов и сид:

```bash
docker compose exec app node dist/db/migrate.js
```

```bash
docker compose exec app node dist/scripts/import-geonames.js
```

```bash
docker compose exec app node dist/db/seed.js
```

`pnpm` в финальном образе нет — только `node` и собранный `dist`.

Оба порта наружу настраиваются: 3000 и 5433 часто заняты другим проектом, тем
более что у контейнеров бывает `restart: unless-stopped` и они поднимаются
вместе с Docker.

```bash
APP_PORT=3100 DB_PORT=5434 docker compose up -d
```

Проверить, кто занял порт:

```bash
docker ps --format '{{.Names}} {{.Ports}}'
```

В проде поставьте `BOT_MODE=webhook`, `PUBLIC_URL` и `WEBHOOK_SECRET` — бот сам
зарегистрирует вебхук на старте. Прод-стенд с Caddy и панелью на одном
домене — в [`deploy/`](../deploy/README.md).

## Панель

[admin-panel](../admin-panel) — отдельное приложение на React, собирается в
статику. Вход через Telegram Login Widget, сессия в httpOnly-куке `jk_admin`
с `SameSite=Lax`: панель и API должны быть на одном сайте (поддомены одного
домена или localhost с разными портами). Для разработки в `.env` нужен
`ADMIN_ORIGIN=http://localhost:5173`.
