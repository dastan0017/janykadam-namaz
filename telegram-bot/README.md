# Janykadam — телеграм-бот марафонов и бэкенд панели

Бот 30-дневных марафонов сообщества Janykadam и API для
[админ-панели](../admin-panel). Node 22, TypeScript, NestJS на Fastify-адаптере,
PostgreSQL 16 через Drizzle, очереди на pg-boss.

## Главный факт

**Один бот обслуживает все марафоны.** Отсюда почти всё устройство:

- вход только по deep link с кодом марафона — `t.me/janykadam_bot?start=m5`;
  бот не может написать первым;
- имя, описание, команды и аватар бота общие, их нельзя развести по марафонам;
- тихие часы и дневной лимит сообщений тоже общие: чат у участницы один;
- участница может вести два марафона сразу. Активный марафон один, каждое
  напоминание начинается с метки `[Название]`, а кнопка в нём переключает контекст.

**Отчёт — только видеокружок.** Он не проверяется: отправка в открытое окно и
есть принятый отчёт. Видео не скачивается, хранятся только `file_id`,
`file_unique_id` и длительность.

Команд, капитанов, кодов команд, модерации и других типов подтверждения не
существует — это проверяется тестом `tests/removed-features.test.ts`.

## Быстрый старт

```bash
corepack pnpm install
```

Поднять базу (PostgreSQL 16) и применить миграции:

```bash
docker compose up -d db
```

```bash
cp .env.example .env
```

```bash
corepack pnpm db:migrate
```

Справочник городов (≈170 тысяч строк, скачивается один раз):

```bash
corepack pnpm import:geonames
```

Базовые данные и демо-марафон:

```bash
SEED_DEMO=true corepack pnpm seed
```

Запуск:

```bash
corepack pnpm build && corepack pnpm start
```

### Про pnpm и Node

pnpm берётся через `corepack` — версия закреплена в поле `packageManager`, а
Node 22 в `.tool-versions`. Если `pnpm` в системе привязан к другой версии Node,
используйте `corepack pnpm` вместо голого `pnpm`.

### Разработка

`tsx` не умеет `emitDecoratorMetadata`, поэтому приложение всегда запускается из
`dist`: без метаданных DI в NestJS получает `undefined`. В двух терминалах:

```bash
corepack pnpm build:watch
```

```bash
corepack pnpm start:dev
```

Скрипты (`db:migrate`, `seed`, `import:geonames`, `compare:aladhan`) декораторов
не содержат и работают под `tsx` напрямую.

## Настройка в BotFather

1. `/newbot` — получить токен, положить в `BOT_TOKEN`.
2. `/setprivacy` → **Disable**, иначе бот не увидит сообщения в группах. Для
   работы это не нужно (бот работает только в личке и выходит из групп), но
   отключённый privacy mode избавляет от сюрпризов.
3. `/setdomain` — домен админ-панели. **Без этого шага Telegram Login Widget не
   работает**: виджет отказывается отдавать данные на незарегистрированный домен.
4. Имя, описание и команды задаются из панели (`PATCH /api/bot/settings`,
   `POST /api/bot/name`), менять их в BotFather не нужно.

## Переменные окружения

| Переменная | Смысл |
| --- | --- |
| `TZ` | Обязательно `UTC`. Процесс падает на старте, если это не так. |
| `BOT_TOKEN` | Токен из BotFather. |
| `BOT_MODE` | `polling` в разработке, `webhook` в проде. |
| `PUBLIC_URL` | Публичный адрес для вебхука (только в режиме webhook). |
| `WEBHOOK_SECRET` | Проверяется в заголовке `X-Telegram-Bot-Api-Secret-Token`. |
| `DATABASE_URL` | PostgreSQL 16. |
| `SESSION_SECRET` | Подпись куки админ-сессии. |
| `ADMIN_ORIGIN` | Origin панели для CORS. |
| `INITIAL_ADMIN_TG_USERNAME` | Кого сид делает первым админом. |
| `SEED_DEMO` | `true` — создать демо-марафон. |

Секреты генерируются так:

```bash
openssl rand -hex 32
```

## Время намазов

Считается локально пакетом `adhan`, в рантайме никаких обращений к API.
Метод — Aladhan № 14 (ДУМ России): Фаджр 16°, Иша 15°, Аср по ханафитскому
мазхабу, высокоширотное правило `recommended`.

Пояс выводится из координат, а не выбирается отдельно: время намаза зависит от
точки. Бишкек и Ош лежат в `Asia/Bishkek`, но расходятся на 5–15 минут.

Сверка с эталоном (инструмент разработчика, в проде не используется):

```bash
corepack pnpm compare:aladhan 2026-11-08
```

Расхождение — ноль по всем временам, кроме Асра: там 1–2 минуты из-за разного
округления длины тени. Выравнивается поправками `bot_settings.prayer_tune`.

Окна намазов полуоткрытые `[открыто, закрыто)` и могут пересекать полночь.
Куптан идёт до следующего фаджра: в Петербурге 21 июня иша наступает в 23:10, и
правило «до полуночи» оставляло бы меньше часа. Отчёт всегда относится к ключу
дня своего окна, а не к календарной дате отправки.

## Города

Поиск по выгрузке GeoNames `cities1000`. И запрос, и индекс сводятся к одной
латинской форме, поэтому «Талас», «Talas» и опечатка «Бишкэк» находят одно и то
же. Кыргызские буквы складываются: `ң→н`, `ө→о`, `ү→у`.

Ранжирование трёхъярусное: точное совпадение с основным именем, затем совпадение
словом среди альтернативных названий, затем триграммы; внутри яруса — по
населению. Без ярусов «Ош» тонул под Лондоном и Найроби: в их `alternatenames`
встречается форма, которая после свёртки даёт слово `osh`.

**Данные о городах: GeoNames (CC BY 4.0), https://www.geonames.org/** — атрибуция
обязана оставаться здесь и в тексте `/help`.

## Что где лежит

```
src/
  config/     разбор окружения
  db/         схема Drizzle, миграции, сид, поиск городов
  domain/     чистая логика: намазы, окна, баллы, напоминания, валидация, тексты
  bot/        grammY: контекст, клавиатуры, флоу регистрации, отчёта и команд
  jobs/       pg-boss: планировщик, напоминания, сводки, рассылки, жизненный цикл
  api/        админ-API, вход через Telegram Login, вебхук, /healthz
  scripts/    импорт GeoNames, сверка с Aladhan
tests/
```

`domain/` не импортирует ни Telegram, ни базу — поэтому её логика проверяется
обычными тестами без окружения.

## Тесты

```bash
corepack pnpm test
```

Нужны применённые миграции, импортированные города и выполненный сид: часть
тестов работает на настоящем Postgres, а флоу бота — через подменённый Telegram
API, наружу ничего не уходит.

## Эксплуатация

Вебхук проверяет секретный заголовок и отсеивает повторные `update_id` за сутки.
Отправка ограничена 25 сообщениями в секунду — общий лимитер на напоминания и
рассылки, поэтому рассылка на 500 человек занимает около двадцати секунд.

`/healthz` проверяет и базу, и pg-boss: без очереди напоминания перестают
уходить совершенно молча.

Координаты округляются до двух знаков. В логи не попадают ни тексты сообщений,
ни ответы на вопросы — только идентификаторы.

### Деплой

```bash
docker compose up -d --build
```

Затем внутри контейнера применить миграции и сид:

```bash
docker compose exec app node -e "require('./dist/db/migrate.js')"
```

В проде поставьте `BOT_MODE=webhook`, `PUBLIC_URL` и `WEBHOOK_SECRET` — бот сам
зарегистрирует вебхук на старте.
